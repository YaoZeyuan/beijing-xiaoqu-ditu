# 北京住宅小区数据（公开版）

北京住宅小区的**小区级与备案级基础数据**，把两个互不相通的数据源接了起来：

- **政府侧**：北京市住建委住宅小区业主大会与业委会备案系统（项目名、区、街道、物业费、物业公司、收费方式、业委会状态）
- **链家侧**：开源小区库（户数、楼栋数、建成年代、经纬度、参考均价、链家小区页）

两边的小区名经常对不上：备案记「今家园」、链家叫「宣海家园」；备案按楼栋拆成多条、
链家合成一条展示。这里用程序规则 + 大模型逐条语义判定做了对齐，并保留置信度。

## 目录

```
raw/          原始数据，未经加工
processed/    把两个源接起来之后的结果
```

### raw/ 原始数据

| 文件 | 行数 | 说明 |
|---|---|---|
| `gov_projects.csv` / `.json` | 10,495 | 政府备案的全量小区项目，已脱敏 |
| `lianjia_2018.csv` / `.json` | 9,878 | 链家开源小区库 2018.11 |
| `lianjia_2019.csv` / `.json` | 10,101 | 链家开源小区库 2019.02 |

两期链家数据可以交叉核对：同一个链家 `community_id` 的户数 **92% 完全一致**，
不一致的多是链家自身修正，可当数据质量参考。

### processed/ 加工结果

| 文件 | 行数 | 说明 |
|---|---|---|
| `xiaoqu.csv` / `.json` | 5,655 | **小区主表**：一行一个小区，按链家小区去重 |
| `matched.csv` / `.json` | 7,194 | 一行一个备案项目，附匹配方式与置信度，可追溯 |
| `beian_master.csv` / `.json` | 10,495 | **备案主表**：一行一条备案，链家信息右挂。业委会状态与公共收益只有这张有 |
| `unmatched.csv` / `.json` | 3,301 | 未匹配的备案项目，附 Top3 候选供人工补匹配 |

匹配结果：**7,194 / 10,495 = 68.5%** 的备案项目找到了对应小区。

## 怎么用

**做小区层面的统计** → `processed/xiaoqu.csv`。
**做备案层面的研究（业委会成立、公共收益、物业费结构）** → `processed/beian_master.csv`。
**查某个备案项目对到哪个链家小区、为什么这么对** → `processed/matched.csv`。
**想自己重跑匹配** → 用 `raw/` 三份数据，`matched` 里有我们用的规则名可以对照。

CSV 全部是 UTF-8 BOM，Excel 双击打开不乱码；JSON 是 `{meta, count, data}` 结构，`data` 为对象数组。

```python
import pandas as pd

```

## 四个必须知道的口径

### 1. 先过滤 `备案登记完整 = 是`

备案库里有一批只填了项目名、区、街道和收费方式的记录（占 19%），
地址、物业公司、物业费明细全空，业委会状态清一色「均未成立」。
这批记录**不成比例地集中在「酬金制」上**（酬金制里 75% 是这种残缺记录，包干制只有 3%）。

不过滤会得出「酬金制小区几乎不成立业委会」的假结论；过滤后两者没有差异。

### 2. 户数来自链家与互联网补查，都不是官方统计

`户数` 是链家一对一匹配到的登记值，2018 / 2019 两期交叉核对过；`AI户数` 是互联网公开页面补查来的。
10,495 条备案里 4,792 条有链家户数、3,324 条有补查户数，合计 **8,115 条（77.3%）** 至少有一个户数值。
补查值带 `AI户数置信度`：A 政府官方 / B 官媒或政府背景媒体 / C 百科或权威行业 / D 房产平台多源互证
（D 需 ≥2 独立源互证且差异 ≤5%）；空表示该值来自早期轮次，未做分级。
个别小区是单栋空壳条目（<6 户），已在源数据里标出。

### 3. `链家为聚合页 = 是` 的户数是合计值

链家把多个院落合成一条展示时，户数是整片街区的合计，不能当作单个小区。
这类记录 `备案项目数` 通常也 >1——做户数分析必须用 `xiaoqu.csv` 去重后的值。

### 4. 剔除非住宅

`是否住宅 = 否` 是写字楼/商场，做住宅分析要排除。

### 5. `AI户数口径` 决定能不能加总

`beian_master` 每条备案一行，户数分两列：`户数`（链家匹配得来）与 `AI户数`（互联网补查得来）。
10,495 条备案里，4,792 条有链家户数、3,324 条有补查户数，
`AI户数口径` 说明每个数是哪种口径：

| 口径 | 条数 | 含义 | 能不能直接加总 |
|---|---|---|---|
| 单条备案 | 2,038 | 链家没匹配上，但网上查到了这一条备案自己的户数 | 能 |
| 本备案分区 | 154 | 查到了该分区/该栋的独立户数 | 能 |
| 整小区合计 | 377 | 这条备案本身就等于整个小区 | 能 |
| 整小区合计·分区未拆 | 755 | 只是小区的一部分，这里放的是**整个小区**的户数作参考 | **不能**，要按 `链家id` 去重 |

最后一行是最容易踩的：这条/这几条备案共同挂着一个链家小区，755 条落在 388 个链家小区上。
网上只查得到小区总数、查不到各分区，于是把小区总数放在每条上并标「分区未拆」——
直接求和会把户数放大。**算户数总量时：按 `链家id` 去重，只数一次。**

完全没户数的还剩 2,380 条：其中 1,284 条是链家侧没有相似候选的真实覆盖缺口，
887 条是匹配成功的单栋楼/院落（链家自身登记为 0 或空），116 条补查也没查到，
其余 93 条是备案区缺失或候选歧义。这些在公开互联网上大概率就没有权威数字了。

### 6. 三种「未匹配」的成因不同，别当成一回事

`beian_master` 的 `匹配类别` 列是 5 类互斥枚举，可直接用来筛样本：

| 匹配类别 | 条数 | 性质 |
|---|---|---|
| 匹配成功 | 7,194 | 链家有对应小区，68.5% |
| AI寻找 | 1,806 | 链家没匹配上，但通过互联网公开页面（百科/房产平台/政府网站）补查到了户数、物业费，见 `AI户数`/`AI物业费`/`AI来源` 列 |
| 未匹配-无相似候选 | 1,391 | 真实覆盖缺口，链家侧可能就没有这个小区 |
| 未匹配-备案区缺失 | 78 | **登记问题**：项目所在区为空，跳过跨区模糊匹配。补上区名后这部分多数能匹配 |
| 未匹配-候选歧义 | 26 | **算法保守**：有多条同名候选，宁可留空也不猜 |

评估「覆盖率」时，把「备案区缺失」从分母里剔除会得到更公允的数字。
`匹配类别` 只回答成没成、为什么不成；**置信度**与链家字段是否齐全属叠加维度，另列。

## 字段

见 `dictionary.csv`，列了每个文件的每个字段含义与实测填充率。

几个容易被忽略但很有用的：

- `房屋性质`：普通商品房 / 房改房 / 央产房 / 回迁房 / 保障房 / 别墅 / 自管公房 / 直管公房。藏在备案的物业费明细里，是这套数据里唯一的产权性质来源，做治理分析时应作为控制变量。
- `物业公司变更`：2019 链家登记 vs 2026 备案登记的比对结果，能看七年里哪些小区换了物业。
- `公共收益是否单独列账`：100% 覆盖，是个现成的治理变量。
- `匹配方式` / `置信度`：`high` 是程序规则完全对应，`medium` 含模型语义判定，`low` 只有模糊名称相似，可按需过滤。

## 已做的脱敏

剔除：业委会与项目负责人的姓名、联系方式、企业法定代表人、统一社会信用代码、企业注册地址。

仓库内另一份正式数据集 `crawler/data/projects.json` 保留字段更全，但所有人都名字段（含企业法定代表人）
与联系电话已按 `crawler/anonymize.py` 打码：姓名留首字、电话留前 3 位、单字名记 `*`，
且按字段名兜底自动覆盖新增的个人信息列。含未脱敏内容的 `raw_data/`、`exports/` 不入库。

保留：物业公司全称、物业费等收费标准、业委会状态、**物业共有部分经营收支金额**
（`beian_master` 的 `公共收益收入` / `支出` / `余额` 三列）——均属政府公示的公共事项。

## 交付格式

对外数据默认 **CSV + JSON 各一份**：本目录下 `raw/` 与 `processed/` 的每个文件都有同名两份，
CSV 为 UTF-8 BOM（Excel 直接打开不乱码），JSON 为 `{meta, count, data}` 结构。

## 口径基准

本项目用于计算北京小区自治情况，**默认以政府备案数据为准**：业委会 / 物管会状态、物业费、
收费方式、公共收益均取备案值，链家与互联网补查只用于补户数、建成年代、经纬度、参考价并标注来源。
默认分母是 10,495 条备案项目；用小区级视图（`xiaoqu.csv` 5,655 行）时必须写明去重口径。

## 已知局限

- 31% 的备案项目在链家找不到对应小区，多为单位家属院、胡同院落、单栋楼。这些没有户数，但物业费、收费方式、业委会状态是有的
- 名称匹配有误差，`置信度 = low` 的建议人工复核
- 「物业公司变更」是字符串比对结果，`疑似` 档需人工确认
- 备案的 `房屋性质` 有 17% 未登记，且缺失不是随机的——它和整条记录的完整度高度相关
- `beian_master` 里「一对多」为 0 例，是匹配阶段每个备案只保留一个最优链家小区所致，不是数据里真的没有
- 公共收益金额原始填报单位未统一，且有 6,000 多行填 0，分不清「真为 0」与「未填」
