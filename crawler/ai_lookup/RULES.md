# AI 检索作业规则

用途：为「政府备案但未与链家数据匹配」的北京小区，在网上检索真实户数与物业费。
工作目录：`D:\win_www\beijing-xiaoqu-map`（所有命令在此执行）

## 输入
批次文件 `raw_data/ai_lookup/batches/batch_XX.txt`，每行一条：

```
序号 | id | 区 | 小区名 | 街道 | 地址 | 备案物业费
```

## 检索
每条先用 WebSearch，查询词形如「北京 {区} {小区名} 户数 物业费」，必要时补街道或地址。
**原则上每条只做 1 次搜索**；仅当结果明确指向某个小区详情页却缺户数/物业费时，才用 WebFetch 打开那一页。

**提速要求（重要）**：在同一轮回复里**并行发起 3–5 个 WebSearch**（查不同的小区），拿到结果后逐条判断、
逐条写盘；不要一条一条串着搜。同一条确实需要打开详情页时，也把多个 WebFetch 并行发出。
一条最多 1 次搜索 + 1 次详情页读取，超出就是浪费时间。

来源优先级：百度百科、中指研究院、吉屋网、安居客、贝壳/链家、楼盘网、房天下、克而瑞、政府网站、开发商或物业公告。

## 判断准则（宁可放弃，也不要填错）

1. **必须是同一个小区。** 搜到上一级地名、更大范围街区、同名但不同区/街道的，一律不算。
   示例：「东交民巷7号院」只搜到「东交民巷」257 户——那是整片街区，属错配，判 ambiguous。

2. **整体与分区不能混用。** 若备案名带分区（「XX小区AB区」「XX一期」「XX南里」「XX城建」），
   只搜到整体户数时，**不能把整体值填成该分区**，应判 ambiguous；或户数留空、只用能对上的物业费。
   这条最容易出错，务必逐条核对备案名是否含分区/期数/楼栋范围。
   **例外**：若备案地址本身就覆盖了全部区（如「丰台区看丹街道富锦嘉园1、2、3、4、5区」），则整体值可用，
   但置信度记 low，并在 reason 说明地址覆盖范围。
   物业费在这种情况下一般仍不能下移——各区报价常不同，只填能与备案对上的那个值。

3. 户数取「总户数 / 规划户数 / 小区户数 / 房屋总数」，单位：户。

4. 物业费必须是「元/㎡·月」。若原文为「元/月」且无面积可换算，放弃该项。
   若为区间（如 5.5–20 元），取低值并在 reason 注明是区间。

5. 备案物业费已在批次文件中给出。搜到的物业费若与之相差 3 倍以上，可能不是同一小区——
   降为 low 或改判 ambiguous，并在 reason 写明。

6. 均价（元/㎡）可选，有就填。

7. 网易号/搜狐号/百家号/微信公众号等自媒体转载只能当佐证，单独出现时置信度最高记 medium。

8. 多来源冲突取多数，reason 里写明分歧。

9. 非住宅物业（酒店、纯写字楼、商场）没有住宅户数口径，判 not_found 或 ambiguous 并说明。

## 必须写盘（断点续传的唯一依据）

每查完一条立刻执行一次（bash；reason 内不要出现英文双引号，用「」代替）：

查到：
```bash
python crawler/ai_lookup_record.py --id <ID> --status found --households <户数> --fee <物业费> --price <均价> --url "<来源URL>" --site "<站点名>" --confidence high|medium|low --reason "<一句话依据>"
```

查不到：
```bash
python crawler/ai_lookup_record.py --id <ID> --status not_found --reason "<查了哪些站、为什么没有>"
```

同名但非同一小区、或只有整体数无法拆分区：
```bash
python crawler/ai_lookup_record.py --id <ID> --status ambiguous --url "<URL>" --reason "<为什么不能采用>"
```

只查到户数或只查到物业费时仍按 found 记录，缺的那项不传参数。
写盘命令**每条只执行一次**；同一 id 再次执行会覆盖旧记录（用于事后修正），不会产生重复行。

## 产出
返回统计：found / not_found / ambiguous 各几条，补到户数几条、补到物业费几条，以及主要障碍。
不要逐条复述。
