# 第二轮作业规则：多对一小区户数补查

工作目录：`D:\win_www\beijing-xiaoqu-map`（所有命令在此执行）

## 这轮在查什么

2,402 条**政府备案**共用了 863 个**链家小区**（一条链家小区被多条备案分担，叫「多对一」）。
这些链家小区在 2018/2019 快照里户数全空，所以备案侧一条户数都没有。

一个小区对应多条备案，通常是这几种关系：

- **分区/分期**：`保利花园` ← `保利花园B区`、`保利花园C区`（各区有独立户数）
- **楼栋/院落拆分**：`东厂胡同` ← `东厂胡同14号、甲14号`、`东厂胡同乙14号楼`（没有独立户数）
- **登记口径不同**：`崇文门西大街` ← `崇文门西大街3号楼`、`崇西小区`

**整小区户数只对「本身就是整小区口径」的备案有效**，不能随手填给各分区。

## 输入

批次文件 `raw_data/ai_lookup/batches_m2/batch_XX.txt`，每块一个小区：

```
## 1  [A] lj=1112995421285636  保利花园  (密云区/鼓楼街道 · 商圈:密云 · 阳光街390号院)
   链家户数：空   备案 2 条（带分区标记 2 条）
   - B2DE5B01CBA04DD1E06000AC01005E2A | 保利花园B区 | 费=2.5 | 密云区宾阳村 | [分区]
   - 9A5BF6E2... | 保利花园C区 | 费=2.5 | 密云区宾阳村 | [分区]
```

- `lj=` 后面是链家 id，**写盘时用它当 key**
- 每行备案：`备案编号 | 备案名 | 备案物业费 | 备案地址`，末尾 `[分区]` 表示名字带 A区/二期/3号楼 这类分区标记

## 检索

**每个小区先搜 1 次**：`北京 {区} {小区名} 户数`（区不明就不写区）。
若小区下有 `[分区]` 备案，且第一搜只给出整小区数、没有分区构成，**再补搜 1 次**：
`{小区名}{A区/C区} 户数`——只补搜有疑问的那一两个分区，不要每个分区都搜。
结果页里给出详情页且只缺户数时，才 WebFetch 打开那一页。

**提速（重要）**：同一轮回复里**并行发起 3–5 个 WebSearch**（查不同小区），拿到结果后逐条判断、逐条写盘。
不要一条一条串着搜。单小区最多 2 次搜索 + 1 次详情页，超出就是浪费。

来源优先级：百度百科、中指研究院、吉屋网、安居客、贝壳/链家、楼盘网、房天下、克而瑞、政府采购网/区政府文件/街道公众号、开发商或物业公告。

## 判断准则（宁可放弃，也不要填错）

1. **必须是同一个小区。** 搜到上一级地名、更大范围街区、同名的另一个区小区，一律不算。
   例：`东厂胡同` 只搜到「东厂胡同一带」的历史介绍——那是街区，判 not_found 或 ambiguous。

2. **整小区 vs 分区**（这轮最容易错的一条）
   - 搜到的数字是**整个小区**的（如「保利花园 27栋 1226户」而备案是 `保利花园C区`）：
     → 不能填给 C 区。只有在**搜索页明确写了「C区 1226户」**时才算 C 区的数。
   - 备案地址本身覆盖全部区（如「…富锦嘉园1、2、3、4、5区」）时，整小区值可用，但置信度记 **low**，reason 写明地址覆盖范围。
   - 物业费和均价同理：分区报价常不同，只在能对上时下移。

3. 户数取「总户数 / 规划户数 / 小区户数 / 房屋总数」，单位：户。

4. 物业费必须是「元/㎡·月」。原文是「元/月」且无面积可换算的，放弃该项。区间（5.5–20 元）取低值并在 reason 注明。

5. 搜到的物业费与批次里给的备案物业费相差 3 倍以上 → 可能不是同一小区，降 low 或改判 ambiguous。

6. 均价（元/㎡）可选，有就填。

7. 网易号/搜狐号/百家号/微信公众号等自媒体转载只能当佐证，单独出现时置信度最高记 medium。

8. 多来源冲突取多数，reason 里写明分歧。

9. 胡同、街道名、号院类小区：整条胡同没有「户数」这种东西，通常判 not_found；
   若某个具体院落（如「XX胡同14号院」）有明确户数，用 `--part` 记给那条备案，不要当整小区值。

10. 非住宅物业（酒店、纯写字楼、商场）没有住宅户数口径，判 not_found 或 ambiguous 并说明。

## 必须写盘（断点续传的唯一依据）

每查完一个小区**立刻**执行一次（reason 里不要用英文双引号，用「」代替）：

**查到整小区数**（`--share` 列出「本身就是整小区口径、可以共用这个数」的备案编号；不写则默认给本小区下**不带 `[分区]` 标记**的备案）：
```bash
python crawler/ai_lookup_record_m2.py --lj 1112995421285636 --status found \
    --households 1226 --fee 2.5 --price 48000 \
    --url "https://baike.baidu.com/item/保利花园C区" --site "百度百科" --confidence high \
    --share B2DE5B01CBA04DD1E06000AC01005E2A \
    --reason "百科词条27栋共1226户，备案即整小区口径"
```

**只查到分区数**（整小区数不明，或各区不等）：
```bash
python crawler/ai_lookup_record_m2.py --lj 1112995421285636 --status found \
    --part 9A5BF6E2...=1226/2.5 \
    --url "..." --site "贝壳" --confidence high \
    --reason "贝壳小区页标注C区1226户、物业费2.5"
```

**整小区 + 分区都有**：`--households` 与多个 `--part` 一起用。
**只查到物业费/均价**：照样 found，只传那项，不传 `--households`。

**查不到**：
```bash
python crawler/ai_lookup_record_m2.py --lj 1112... --status not_found --reason "百科/贝壳/安居客均无该小区页，只搜到街道级介绍"
```

**搜到同名但不是这个小区，或只有整体数无法拆分区**：
```bash
python crawler/ai_lookup_record_m2.py --lj 1112... --status ambiguous --url "..." --reason "只有整小区户数，备案为C区，不能下移"
```

写盘命令**每个小区只执行一次**；同一 key 重复执行会覆盖旧记录（用于事后修正），不产生重复行。

**严禁**读取后重写 / 清理 / 去重 `results_m2.jsonl`——多进程共享追加写，重写会冲掉别人的记录。
写盘只能通过 `crawler/ai_lookup_record_m2.py`。发现坏行跳过即可，不要修复。

## 产出

返回统计：found / ambiguous / not_found 各几个小区，补到整小区户数几个、分区户数几条、物业费几条，
以及主要障碍（一句话）。不要逐条复述。
